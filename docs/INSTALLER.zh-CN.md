# Acbric 玩家使用指南（dev.33）

[English](INSTALLER.md)

## 第一次使用

1. 完整解压带 Java 的发行包，打开其中 `Acbric` 文件夹的 **Acbric.exe**。游戏需要另外安装。
2. 启动器自动查找 Steam 中的游戏。确认显示的位置后，点击 **使用此游戏**。找不到或找到了另一份游戏时，点击 **选择游戏文件夹**。
3. 准备完成后，点击 **开始游戏**。以后仍然打开同一个 EXE，不必重复配置。

右上角可切换中文/English，选择会保存。默认数据位置自动配置；普通玩家不需要了解“实例”。游戏运行期间，启动器等待游戏关闭再恢复操作。

```text
Acbric/
├─ Acbric.exe            唯一日常入口
├─ mods/                 放置 MOD
├─ 使用说明.txt / QUICK_START.txt
├─ docs/                 完整说明
├─ advanced/             旧版配置、启动与维护工具
├─ core/、loader-libs/、runtime/ 等运行文件
└─ instances/default/    首次配置后创建的数据目录
```

只提供一个 EXE **入口**，不是把整个框架压成一个文件。请保留完整目录；桌面访问可以创建 EXE 的快捷方式。发行包运行文件中的 PowerShell 脚本无需玩家手动打开。

## 添加 MOD

点击 **打开 MOD 文件夹**：Java MOD 放入 `.jar`；原版 MOD 放入直接含 `info.json` 的文件夹。`.amod` 通过游戏内“安装 MOD”导入。API 已内置，勿再放一份 API JAR。增删和启停 Java MOD 后需要重启游戏。

旧布局/User 目录不会自动导入。需要的 MOD 请关闭游戏后手动复制。存档和游戏设置位于 `instances/default/userdata`，MOD 设置在 `instances/default/config`。多个实例共用同层 `mods`，但配置和存档独立。

## 设置与维护

- **更换游戏位置**：游戏搬家或选错目录后使用。保留原数据目录，再确认新游戏位置。
- **安装更新包**：关闭游戏，在设置中选择可信的 `Acbric-external-<version>.zip`。启动器退出后执行更新，成功后自动重开。不要直接将更新包覆盖解压到旧目录。
- **恢复上一版**：恢复最近一次更新前的框架文件。MOD、存档、设置不回滚；旧框架不一定能读新版本保存的数据。
- **高级设置**：需要自定义数据目录、切换已有实例时使用。选择实例后读取、检查、保存；日常无需打开。

首次从 dev.32 或更早版更新到本版：把新包解压到另一处，运行新包的 `advanced/Update Acbric.cmd`，选择原 Acbric 目录和新 ZIP。旧更新器不认识 EXE 文件清单。无受支持清单的旧版按新安装流程配置；不自动迁移旧数据。此兼容入口仅用于旧版升级/故障救援，后续可在 EXE 中更新。

更新继续核对归属清单、文件哈希和核心版本；修改过的文件、路径冲突和占用会阻止替换。校验不代表发布者身份认证。保留 `.acbric-maintenance` 备份；中断更新时 EXE 会提示先恢复。若入口本身损坏或缺失，用另一份完整新包中的维护工具选择原目录恢复。恢复前不要搬迁目录。

## 遇到问题

普通界面显示可读说明和 **重试**，不直接显示 Java 堆栈。进入 **帮助 → 导出诊断** 保存 ZIP，再自行发送给开发者。导出前会说明内容：版本、近期启动器/游戏启动日志及可能包含的本机路径；不包含存档、不自动上传。每类最多 10 份日志、每份最多 1 MiB、总日志最多 10 MiB，大日志截断。已有同名报告不会覆盖。

**帮助 → 技术详情** 只在主动打开时展示本次操作的详细异常。最早期失败、Java 缺失或 GUI 尚未打开时，EXE 显示简短提示和“打开诊断文件夹”。

排错文件位置：

- 启动器/维护日志：`%LOCALAPPDATA%/Acbric/launcher-logs`。
- 完整游戏启动输出：`<实例>/logs/acbric/launcher/launch-*.log`。
- 原生日志：`<实例>/userdata/log.txt`，需要时另行提供；自动报告不收集整个 userdata。
- 高级安装工具保存失败时仍记录临时目录 `acbric-setup-*.log`；普通流程异常收进启动器日志。

配置损坏时不会自动清空重建或猜测另一份存档。保留文件并导出诊断；不要创建空的 instance.json。首次保存保留目录原子发布、占用重试和锁保护。

## 搬迁与边界

移动整个 Acbric 文件夹后再次打开 EXE，确认游戏即可更新原实例的框架位置。外部实例路径变化需在高级设置中明确选择原目录。包内实例绑定使用相对路径，外部实例使用绝对路径。

当前面向 Windows x64。面向玩家使用带 Java 21 的包；不带运行时的包需要有效 `JAVA_HOME`。EXE 尚未代码签名。没有自动联网更新、自动导入旧数据或卸载向导。原生 GL、任意 MOD 组合和跨设备表现仍需针对性验收。
