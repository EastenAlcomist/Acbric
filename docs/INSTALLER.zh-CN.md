# Acbric 玩家使用指南（0.3.5.1）

[English](INSTALLER.md)

## 第一次使用

1. 完整解压带 Java 的发行包，打开其中 `Acbric` 文件夹的 **Acbric.exe**。游戏需要另外安装：本版**适配《Airships: Conquer the Skies》1.2.15.3**（含 LWJGL3 引擎后端的引擎迁移 MOD），1.2.15.2 等旧引擎版本同样可用。
2. 启动器自动查找 Steam 中的游戏。确认显示的位置后，点击 **使用此游戏**。找不到或找到了另一份游戏时，点击 **选择游戏文件夹**。
3. 准备完成后，点击 **开始游戏**。以后仍然打开同一个 EXE，不必重复配置。
4. 想沿用原版游戏里的存档、设计和 MOD 时，点击首页的 **一键同步**（见下文）。

右上角可切换中文/English，选择会保存。默认数据位置自动配置；普通玩家不需要了解“实例”。游戏运行期间，启动器等待游戏关闭再恢复操作。

```text
Acbric/
├─ Acbric.exe            唯一日常入口
├─ mods/                 放置 MOD
├─ 使用说明.txt / QUICK_START.txt
├─ docs/                 完整说明
├─ advanced/             旧版配置、启动与维护工具
├─ core/、loader-libs/、runtime/ 等运行文件
└─ instances/default/    首次配置后创建的数据目录
```

只提供一个 EXE **入口**，不是把整个框架压成一个文件。请保留完整目录；桌面访问可以创建 EXE 的快捷方式。发行包运行文件中的 PowerShell 脚本无需玩家手动打开。

## 添加 MOD

点击 **打开 MOD 文件夹**：Java MOD 放入 `.jar`；原版 MOD 放入直接含 `info.json` 的文件夹。`.amod` 通过游戏内“安装 MOD”导入。API 已内置，勿再放一份 API JAR。增删和启停 Java MOD 后需要重启游戏。

旧布局/User 目录不会自动导入；默认新实例直接使用原版存档与模组（见下一节），不需要复制。MOD 设置在 `instances/default/config`。多个实例各自记录自己的数据环境，共享模式下共用原版数据，隔离模式各用各的副本。

## 一键同步（直接使用原版存档与模组，不复制）

默认情况下 Acbric **不复制**任何存档或 MOD，而是直接操作原版游戏的数据。首页底部的 **一键同步** 会自动识别原版位置并让这个实例使用它，点一次即可：

- 自动识别：优先读游戏安装目录里 `launch_settings.json` 的 `customDataDirectoryLocation`（在原版里改过数据目录时），否则用 `%APPDATA%\AirshipsGame`，即 `C:\Users\<用户名>\AppData\Roaming\AirshipsGame`。
- 直接使用：`saves`（存档）、`ships` / `buildings` / `landships`（设计）、`combats`（战役）、`missions`（任务）、`recordings` 与 `recordingsArchive`（录像），以及 `mods` 下的原版 MOD 文件夹，全部仍留在原版目录里。
- 磁盘上只有一份：游戏启动时 Acbric 把原生数据目录与原生 MOD 扫描都指向该目录，Acbric 不做第二份拷贝，所以不额外占空间，也不存在两份数据不一致的问题，原版游戏和 Acbric 共用同一份。
- Java MOD（`.jar`）仍然放在与 `Acbric.exe` 同层的 `mods` 文件夹：原版游戏不加载 Fabric MOD，这一份不会重复。

同步不写入、不删除任何文件，因此点击后不弹确认，只在状态栏显示识别到的路径。原版目录里没有文件时（例如从未运行过原版游戏），会提示先运行一次原版，或改用下面的环境隔离。

## 环境隔离（可选）

需要让 Acbric 使用自己的一份数据、不再直接改动原版时，打开 **设置 → 环境隔离**：

1. 先关闭游戏；游戏运行中或另一个实例占用 MOD 目录时会拒绝。
2. 确认窗口列出将要复制与移除的数量、原版数据位置和范围。
3. 确认后先把原版数据镜像到实例副本（`instances/default/userdata` 与 Acbric 的 `mods`），成功后再切换模式；复制是**完全镜像**，副本里多出的条目会移除，被覆盖或被移除的内容先备份到 `instances/default/userdata/.acbric-sync-backup/<时间戳>/`（内部分 `userdata/` 与 `mods/`，结果窗口会给出路径）。
4. 隔离后可以再次打开 **设置 → 环境隔离** 按当前原版数据刷新副本；点首页 **一键同步** 则改回直接使用原版（副本会保留在磁盘上，不会被删除）。原版目录中的文件始终不会被删除。

## 设置与维护

- **更换游戏位置**：游戏搬家或选错目录后使用。保留原数据目录，再确认新游戏位置。
- **环境隔离**：让这个实例改用自己的一份存档与 MOD（见上一节），适合想同时保留两套进度、或担心影响原版的玩家。
- **安装更新包**：关闭游戏，在设置中选择可信的 `Acbric-external-<version>.zip`。启动器退出后执行更新，成功后自动重开。不要直接将更新包覆盖解压到旧目录。
- **恢复上一版**：恢复最近一次更新前的框架文件。MOD、存档、设置不回滚；旧框架不一定能读新版本保存的数据。
- **高级设置**：需要自定义数据目录、切换已有实例时使用。选择实例后读取、检查、保存；日常无需打开。

首次从 dev.32 或更早版更新到本版：把新包解压到另一处，运行新包的 `advanced/Update Acbric.cmd`，选择原 Acbric 目录和新 ZIP。旧更新器不认识 EXE 文件清单。无受支持清单的旧版按新安装流程配置；不自动迁移旧数据。此兼容入口仅用于旧版升级/故障救援，后续可在 EXE 中更新。

更新继续核对归属清单、文件哈希和核心版本；修改过的文件、路径冲突和占用会阻止替换。校验不代表发布者身份认证。保留 `.acbric-maintenance` 备份；中断更新时 EXE 会提示先恢复。若入口本身损坏或缺失，用另一份完整新包中的维护工具选择原目录恢复。恢复前不要搬迁目录。

## 遇到问题

普通界面显示可读说明和 **重试**，不直接显示 Java 堆栈。进入 **帮助 → 导出诊断** 保存 ZIP，再自行发送给开发者。导出前会说明内容：版本、近期启动器/游戏启动日志及可能包含的本机路径；不包含存档、不自动上传。每类最多 10 份日志、每份最多 1 MiB、总日志最多 10 MiB，大日志截断。已有同名报告不会覆盖。

**帮助 → 技术详情** 只在主动打开时展示本次操作的详细异常。最早期失败、Java 缺失或 GUI 尚未打开时，EXE 显示简短提示和“打开诊断文件夹”。

排错文件位置：

- 启动器/维护日志：`%LOCALAPPDATA%/Acbric/launcher-logs`。
- 完整游戏启动输出：`<实例>/logs/acbric/launcher/launch-*.log`。
- 原生日志：`<实例>/userdata/log.txt`，需要时另行提供；自动报告不收集整个 userdata。
- 环境隔离备份：`<实例>/userdata/.acbric-sync-backup/<时间戳>`，含隔离时被替换或移除的内容，不需要时自行删除。
- 高级安装工具保存失败时仍记录临时目录 `acbric-setup-*.log`；普通流程异常收进启动器日志。

配置损坏时不会自动清空重建或猜测另一份存档。保留文件并导出诊断；不要创建空的 instance.json。首次保存保留目录原子发布、占用重试和锁保护。

## 搬迁与边界

移动整个 Acbric 文件夹后再次打开 EXE，确认游戏即可更新原实例的框架位置。外部实例路径变化需在高级设置中明确选择原目录。包内实例绑定使用相对路径，外部实例使用绝对路径。

当前面向 Windows x64。面向玩家使用带 Java 21 的包；不带运行时的包需要有效 `JAVA_HOME`。EXE 尚未代码签名。没有自动联网更新、自动旧数据导入或卸载向导；默认直接使用原版数据，只有玩家在 **设置 → 环境隔离** 里主动选择时才会复制一份副本。原生 GL、任意 MOD 组合和跨设备表现仍需针对性验收。
